
# Hybrid Model Methodology Notes

## Motivation

Traditional software vulnerability detection approaches often rely on either manually engineered features or single-model transformer architectures. However, source code contains both semantic and structural information that may contribute to vulnerability identification.

CodeBERT primarily captures semantic and contextual relationships in source code through transformer-based language modeling. GraphCodeBERT extends this capability by incorporating graph-aware structural representations derived from code relationships.

The hybrid architecture was therefore designed to combine these complementary representations into a unified vulnerability detection framework.

---

# Architecture Overview

The proposed hybrid model consists of two parallel transformer branches:

1. CodeBERT branch
2. GraphCodeBERT branch

Both models independently process the same tokenized source code input.

The CLS embeddings generated by each transformer are extracted and concatenated to form a combined feature representation.

This combined representation is passed into a multi-layer perceptron classifier consisting of:
- linear layer
- ReLU activation
- dropout regularization
- output classification layer

The classifier produces binary predictions:
- vulnerable
- benign

---

# Training Strategy

To reduce computational cost and stabilize experimentation, the transformer backbones were initially frozen during training.

Only the classifier head parameters were updated during optimization.

This design choice reduced GPU memory usage and enabled faster experimentation while preserving pretrained transformer representations.

---

# Advantages

The hybrid architecture attempts to combine:
- semantic reasoning from CodeBERT
- structural reasoning from GraphCodeBERT

This may improve vulnerability-sensitive representation learning compared to single-model approaches.

The architecture also provides a modular framework for future extension and experimentation.

---

# Limitations

The architecture increases computational complexity due to the simultaneous use of two transformer models.

Performance results may also be influenced by limitations of the Juliet dataset, including synthetic structural regularities and benchmark leakage effects.

Further evaluation on real-world datasets would be required to assess generalization capability.
